# G0 교차 검토 — 30분

이 리포는 계약(`prd.md` §2)을 먼저 쓰고 그 계약을 픽스처로 못 박은 뒤 구현하는 프로젝트다. 지금 G0(계약 동결) 문턱에 있고, 기계가 확인할 수 있는 것은 전부 초록이다. **남은 것은 사람 둘이 계약을 읽고 서로 모순되는 곳이 있는지 보는 일**이고, 그중 한 명은 이 리포에 커밋한 적이 없어야 한다.

```sh
git clone https://github.com/scndry/jqradar && cd jqradar
python3 -m pip install -r schemas/requirements.txt
python3 docs/review/g0-review.py            # 5분 — 기계가 확인한 것을 한 표로, 그리고 당신이 읽을 쌍 열넷
python3 docs/review/g0-review.py --pairs | less    # 쌍마다 두 절의 본문을 나란히
python3 docs/review/g0-review.py --record <이름>   # 기록 파일
```

## 무엇을 보는가

"계약이 존재하는가"가 아니라 **"계약이 서로 모순 없이 실행되는가"**. 지금까지 실제로 난 충돌 넷은 전부 한 절 안에서는 보이지 않았고, 두 절을 **함께** 실행하려 할 때 드러났다 — 모집단 정의와 F 렌즈, 시간 기준점, 검증과 해소, 전이 귀속. 스크립트가 그 넷이 났던 자리와 같은 종류의 쌍 열넷을 골라 주고, 쌍마다 세 질문을 던진다:

1. 두 절이 같은 이름을 **다른 뜻**으로 쓰는가?
2. 한 절이 요구하는 것을 다른 절이 **불가능하게** 하는가?
3. 두 절을 순서대로 실행하면 **정의되지 않은 상태**가 생기는가?

판정은 셋 중 하나 — **모순 없음 / 모순 / 모호**. 모호도 발견이다.

## 무엇을 보지 않아도 되는가

- 코드. 범위는 `prd.md` §2.1–2.9의 **문장**이다. 구현은 아직 없다(G0).
- 픽스처가 도는지. 스크립트가 돌린다 — 82종.
- 숫자가 맞는지. 본문의 18.1·150·185.48·2.76은 계산에서 나오고, 스크립트가 그것을 대조한다.

## 이 자료를 만든 것은 도구다

계약을 쓴 것도, 픽스처를 쓴 것도, 이 스크립트와 쌍 여덟을 고른 것도 같은 도구(Claude)다. 그 도구가 계약을 잘못 읽었다면 그 오독은 픽스처·스크립트·쌍 목록에 **똑같이** 들어가 있다 — 셋이 서로를 확인해 주지 못한다. 그래서 스크립트는 "통과"를 말하지 않고, 기계가 확인한 것과 당신이 확인할 것을 가른다. **쌍 열넷이 끝나면 목록에 없는 절 둘을 당신이 골라**(쌍 15) 같은 세 질문을 던져 주기 바란다 — 도구가 못 본 쌍은 목록에도 없다. 쌍 16은 배정이다(아래 라운드 절).

**대응표를 먼저 만들고 종합을 거기서 뽑는다.** 종합을 먼저 쓰면 발견이 떨어진다 — 1차가 일곱, 2차가 셋을 떨어뜨렸고 대응표를 나중에 만들면서야 드러났다. 대응표에는 무결성 검사(부착 + 미부착 = 총, 중복 0, 쪼갬)가 있고 종합에는 없다.

기록 파일은 `docs/review/records/`에 생기고, **리뷰어가 PR로 올린다** — 기록도 리포에 남는다. 통과시키지 않기로 한 판단, 모호로 남긴 쌍, 목록 밖에서 직접 고른 절 둘까지 같은 파일에 적는다(§9 자기 적용 규칙: 결과가 나쁘면 그것도 기록한다). 결과는 기록 파일에 적고, 발견은 고치지 말고 인용만 한다. 결정은 소유자가 `prd.md` §0·§10에 한다. 통과시키지 않기로 한 판단도 같은 자리에 적는다 — 그것은 도구가 일하고 있다는 증거다.

자세한 대응표·미결 목록은 [`../g0-review-packet.md`](../g0-review-packet.md). 먼저 읽을 필요는 없다 — 스크립트가 필요한 것을 꺼내 준다.

## 라운드 — 입력을 바꾼다 (D151)

**범위 밖 목록은 생성된다.** `python3 docs/review/g0-review.py --g3-list`가 종합 기록에서 범위 밖 key(D152 — 절 집합에 §2.1–2.9가 없는 것)를 뽑아 [`g3-list.md`](g3-list.md)를 쓴다 — 열린 것과 닫힌 것(D153의 표시, 수에 닿지 않는다)을 갈라, 라운드 → key 순으로, 출처는 개별 기록의 줄로. `ci/check-all.sh`가 `--g3-list --check`로 파일과 생성기 출력의 diff 0을 확인하므로 그 파일은 손으로 고치지 않는다 — 기록을 고치고 다시 생성한다. G3 입장 조건(§6.3–6.6 교차 검토·값 층 픽스처)의 입력이다.

G0 #1의 정지 조건은 "열린 발견 0"이 아니라 **입력을 바꾼 두 라운드 연속, 범위 안 새 발견 0 ∧ 목록 밖 새 발견 0**이다(D151). 1차(동일 모델 5)·2차(Haiku·Sonnet·Opus·Fable)는 **같은 입력**이었고, 둘 다 목록 밖이 목록 안보다 생산적이었다 — 같은 입력의 반복은 같은 맹점을 반복한다. 다섯 한 줄 판(D174–D178) 뒤 `--count`가 낸 열림 0은 세 번째로 계산된 수이지만 정지 조건이 아니다(§0-38).

**3차 라운드의 입력(2026-10-06)** — 바꾸는 방법 셋, 전부 D151(b)의 "쌍 목록의 이력·볼 것 갱신 또는 쌍 추가"다:

1. **쌍 1–8의 이력에 닫은 D를, "볼 것"은 "결정이 다른 절과 또 어긋났는가"로.** 1·2차가 잡은 것은 전부 결정이 §10에 있고 본문이 따라오지 않은 자리였다 — 결정을 다시 묻는 것이 아니라 결정이 이웃 절에 내려갔는지를 본다.
2. **§2 내부 쌍 셋 추가(9–11)** — 기록 다섯이 "거의 보지 않았다"고 적은 축(토크나이저, 투영의 방향, 단위의 끝).
3. **D174–D178이 만든 접점 셋 추가(12–14)** — 결정이 방금 본문에 내려갔으니 이웃과의 어긋남이 가장 신선한 자리.

**쌍 15 = 자유, 쌍 16 = 배정.** D151은 "각 모델이 목록 밖 절 둘을 **직접** 고른다"다 — 출발점을 배정하면 고른 것이 아니다. 배정의 가치(1·2차가 안 간 §2.9·§7.1·§4.4·§6.3을 덮는 것)는 따로 있으니 둘 다 갖는다: 쌍 15는 D151 그대로 자유, 쌍 16은 이번 라운드만의 배정(`--pairs` 끝에 리뷰어 번호별로). D151은 "≥"라 하나 더하는 것은 계약 변경이 아니다.

**입력 해시.** `--pairs`가 머리에 `입력: pairs@<해시>`를 찍고 기록 템플릿이 그것을 머리에 적는다(`--input-hash`만 따로 볼 수도 있다). "입력이 바뀌었다"가 사람의 말이면 확인할 수 없다 — 다음 라운드의 기록이 같은 해시면 그 라운드는 "연속"의 둘째가 아니다. 해시는 쌍 목록·세 질문·배정만 먹고 `prd.md` 버전은 먹지 않는다(본문만 바뀐 라운드는 D151(b)의 입력 변경이 아니다).

**`--verify`를 먼저 돌린다.** 1·2차 리뷰어 넷 다 돌리지 않았다. 3차는 기록 머리에 그 출력의 첫 행과 마지막 줄을 붙인다 — 기계가 본 것과 못 본 것의 경계를 리뷰어가 알고 시작하도록.

**범위 밖은 미리 예고한다.** 쌍 12–14와 쌍 16은 §5.5·§6.3·§5.3·§7.1을 겨누므로 그 발견의 다수는 D152의 절 집합 규칙으로 **밖 → G3 목록**이다. 그것이 맞는 결과이고 종합자가 범위 안으로 끌어오지 않는다("세지 않고 버리지도 않는다"). 라운드 뒤 "범위 안 새 발견 0, 범위 밖 n"이 나와도 그 0은 정직한 0이다. 반대로 쌍 9–11은 §2 내부라 발견이 나오면 전부 안이다 — 이 라운드의 정지 조건은 사실상 쌍 1–11이 정한다.

**패널.** 실행 모델 넷(2차와 같아도 된다 — D151이 허용하는 "같은 모델·다른 입력"; 다른 혈통을 하나 더 넣을 수 있으면 넣되 요건은 아니다, §0-23), 같은 `--pairs` 출력, 세 질문, 판정 셋. 기록은 `- key 접두어:`를 선언하고 `절:` 줄이 `dedupe_key`의 정본이다(D152). **종합은 대응표 먼저.** 새 발견 0이면 D151의 첫 라운드이고 둘째는 다시 입력을 바꿔야 한다. 새 발견이 나오면 결정 판으로 가고 그 뒤 쌍 목록이 또 바뀐다.
