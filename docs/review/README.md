# G0 교차 검토 — 30분

이 리포는 계약(`prd.md` §2)을 먼저 쓰고 그 계약을 픽스처로 못 박은 뒤 구현하는 프로젝트다. 지금 G0(계약 동결) 문턱에 있고, 기계가 확인할 수 있는 것은 전부 초록이다. **남은 것은 사람 둘이 계약을 읽고 서로 모순되는 곳이 있는지 보는 일**이고, 그중 한 명은 이 리포에 커밋한 적이 없어야 한다.

```sh
git clone https://github.com/scndry/jqradar && cd jqradar
python3 -m pip install -r schemas/requirements.txt
python3 docs/review/g0-review.py            # 5분 — 기계가 확인한 것을 한 표로, 그리고 당신이 읽을 쌍 여덟
python3 docs/review/g0-review.py --pairs | less    # 쌍마다 두 절의 본문을 나란히
python3 docs/review/g0-review.py --record <이름>   # 기록 파일
```

## 무엇을 보는가

"계약이 존재하는가"가 아니라 **"계약이 서로 모순 없이 실행되는가"**. 지금까지 실제로 난 충돌 넷은 전부 한 절 안에서는 보이지 않았고, 두 절을 **함께** 실행하려 할 때 드러났다 — 모집단 정의와 F 렌즈, 시간 기준점, 검증과 해소, 전이 귀속. 스크립트가 그 넷이 났던 자리와 같은 종류의 쌍 여덟을 골라 주고, 쌍마다 세 질문을 던진다:

1. 두 절이 같은 이름을 **다른 뜻**으로 쓰는가?
2. 한 절이 요구하는 것을 다른 절이 **불가능하게** 하는가?
3. 두 절을 순서대로 실행하면 **정의되지 않은 상태**가 생기는가?

판정은 셋 중 하나 — **모순 없음 / 모순 / 모호**. 모호도 발견이다.

## 무엇을 보지 않아도 되는가

- 코드. 범위는 `prd.md` §2.1–2.9의 **문장**이다. 구현은 아직 없다(G0).
- 픽스처가 도는지. 스크립트가 돌린다 — 82종.
- 숫자가 맞는지. 본문의 18.1·150·185.48·2.76은 계산에서 나오고, 스크립트가 그것을 대조한다.

## 이 자료를 만든 것은 도구다

계약을 쓴 것도, 픽스처를 쓴 것도, 이 스크립트와 쌍 여덟을 고른 것도 같은 도구(Claude)다. 그 도구가 계약을 잘못 읽었다면 그 오독은 픽스처·스크립트·쌍 목록에 **똑같이** 들어가 있다 — 셋이 서로를 확인해 주지 못한다. 그래서 스크립트는 "통과"를 말하지 않고, 기계가 확인한 것과 당신이 확인할 것을 가른다. **쌍 여덟이 끝나면 목록에 없는 절 둘을 당신이 골라** 같은 세 질문을 던져 주기 바란다 — 도구가 못 본 쌍은 목록에도 없다.

결과는 기록 파일에 적고, 발견은 고치지 말고 인용만 한다. 결정은 소유자가 `prd.md` §0·§10에 한다. 통과시키지 않기로 한 판단도 같은 자리에 적는다 — 그것은 도구가 일하고 있다는 증거다.
