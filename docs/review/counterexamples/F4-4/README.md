# F4-4 — `authors_window_days`의 설명과 공식 (반례 (A) 불일치 · 게이트 G0 — `history/`)

- **인용**: §2.7 "`authors_window_days`(90일 지표가 실제로 본 일수 = `max(0, min(90, HEAD_TIME − 창의 가장 오래된 커밋 시각))` — **유리수 일** …) … "90일을 다 못 봤다"가 아니다: 10일 된 리포는 90일을 못 봤지만 잃은 것이 없고".
- **입력**: `contract/history/window-outside-last-commit-recovered/input.json` — 400일 된 리포, 창(12개월) 안 커밋은 HEAD 하나.
- **두 값**(`run.py`가 계산한다): 설명 문장의 뜻("90일 지표가 실제로 본 일수" — 창이 덮은 90일 구간, 리포의 첫 커밋부터) **90** vs 같은 문장의 공식이자 history 계산기의 값(창 안 가장 오래된 커밋 = HEAD부터) **0**.
- **무엇이 갈리나**: "본 일수 0"은 `truncated: false`와 함께 읽어도 "데이터를 잃었다"로 읽힌다 — §2.7이 `truncated`에 대해 막으려 한 바로 그 오독. 공식을 고치면 픽스처(`0.00` → `90.00`)가 움직이고, 설명을 고치면 문장이 움직인다.
- **게이트**: 값이 `history/` 스위트(G0)의 것 → G0(D266).
