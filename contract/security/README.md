# `security/` — 실행 보안 계약 (§6.6) · 게이트 **G3**

## 이 계약이 고정하는 것

**LLM이 속아도 피해 경로가 없다**는 것을 벡터별로 확인한다(B.5, D21·D33).

- **L1 / L1′ / L2**. L1(`scan`·`change`·`check`·`ledger`)은 대상 코드를 실행하지 않지만 **분석기가 공격받지 않는다는 뜻은 아니다** — PMD·CPD·ASM·JGit은 파서이고 입력은 hostile PR일 수 있다. 신뢰하지 않는 리포의 L1 분석도 프로세스 격리 + 메모리·시간 상한이 필수다(L1′, D97). L2(`apply`·`validate`·`open_pr`)는 샌드박스 필수.
- **구조적 방어가 마지막 선.** 프롬프트 수준 방어는 "필요하지만 충분하지 않은" 층이고, 충분성은 **출력 스키마 제약**이 담당한다 — LLM 출력은 `{option_id ∈ propose가 낸 집합, edits: [{path ∈ 소스 루트, unified_diff}]}`만. 셸·git 명령, 경로 밖 파일, 네트워크 대상, 빌드 스크립트 변경은 **스키마상 표현 불가**여야 한다.
- **감사 로그는 샌드박스 밖**(D97). 샌드박스는 임시라 그 안의 로그는 의미가 없다.

## 최소 케이스 — P9 벡터 (§9)

외부 통신 · 환경변수 읽기 · 호스트 경로 · 시간 초과 · fork bomb · FD 고갈 · 디스크 고갈 · `/proc`·`/sys` 접근 · 컨테이너 capability · Docker 소켓 · DNS 리바인딩 · 의존성 혼동 · **허용 저장소 손상**(캐시 미스 강제) · 심링크 탈출.

전부 미작성. **하나라도 성공하면 L2 출시 보류**(P9 깨짐 기준).

P9는 **알려진 벡터만** 검사한다 — 컨테이너 탈출과 프롬프트 인젝션의 새 변종은 잔여 위험으로 남는다(§12).
