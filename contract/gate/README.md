# `gate/` — 변경 델타·게이트 계약 (§5.2–5.3) · 게이트 **G1**

## 이 계약이 고정하는 것

**게이트가 백분위 드리프트에 흔들리지 않는다**는 것과 **새 중복이 무엇인가**를 못 박는다.

- **BASE 자격 고정 + 원값 델타**(D19). "BASE H top-decile"의 멤버십은 BASE 스캔에서 정해져 얼고, 게이트 조건은 `cx`·중복·순환의 **원값** 델타다. HEAD에서 모집단이 바뀌어 백분위가 움직여도 판정이 바뀌면 안 된다.
- **새 중복은 발생(occurrence) 수준**(D40). 클러스터 해시만 보면 `BASE: A↔B` → `HEAD: A↔C`가 "기존"으로 보여 **새 사본 C를 놓친다**. 정의: HEAD의 발생 ≥ 2인 클러스터에 속한 발생 중 `(rename 매핑 후 경로, 클러스터 ID)`가 BASE의 어떤 발생에도 없는 것. 단순 rename은 매핑이 흡수한다.
- **NCCD 게이트의 `context_changed`**(D98) — 컴포넌트 집합이 바뀌면 WARN 대신 `context_changed`. N 변화와 의존 악화를 섞지 않는다.
- `change.json`의 각 항목은 `{value_base, value_head, delta, evidence[]}`이고 **판정 단어가 없다**(§5.1). 판정은 `check`와 사람이 한다.

## 최소 케이스 (§2.9)

| 케이스 | 무엇을 잡나 | 상태 |
|---|---|---|
| BASE 자격 고정 | top-decile 멤버십이 BASE에서 얼고 HEAD 재계산에 흔들리지 않는다 | 미작성 |
| 모집단 드리프트 무영향 | HEAD에서 파일이 늘어 백분위가 움직여도 게이트 결과 동일 | 미작성 |
| **발생 수준 새 중복** | `A↔B → A↔C`는 **잡고**, `B→C` 단순 rename은 **무시**한다 | 미작성 |
