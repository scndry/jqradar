# `reproducibility/` — 식별자·환경 계약 (§2.8) · 게이트 **G0**

## 이 계약이 고정하는 것

**"같다"가 세 가지 다른 뜻을 갖는다는 것**을 못 박는다(§2.8, D86).

| 정체성 | 무엇이 같으면 같은가 | 쓰임 |
|---|---|---|
| `repository_state_id` | 트리(정렬된 `(path, content_id)` 전체의 sha256) | 캠페인 앵커의 봉인(§5.4, D112) |
| `analysis_input_id` | 트리 **+ 툴체인 + 계약 버전 + 파라미터** | 캐시 키 |
| `validated_tree_id` | 검증이 실제로 돈 트리 | 검증의 증거 결속(§6.3 5a, D89) |

그리고 두 원칙을 실행 가능하게 만든다(B.4):

- **포함되지 않은 입력은 결과에 영향을 주어서는 안 된다.** 환경변수 하나 바꿨는데 숫자가 달라지면 캐시가 거짓말을 한다.
- **포함된 모든 입력은 `reproduce`에 값 또는 해시로 나타나야 한다**(D111). 인쇄된 것만으로 id를 다시 만들 수 없으면 그 id는 의견이다.

## 최소 케이스 (§2.9)

| 케이스 | 무엇을 잡나 | 상태 |
|---|---|---|
| 같은 트리·다른 PMD 버전 | `analysis_input_id` **다름** ∧ `repository_state_id` **같음**. 툴체인이 키에 빠지면 PMD 7.16과 7.17이 같은 키를 만든다 | 미작성 |
| 파라미터 하나 변경 | `cpd.minimum_tokens` 100→120에 `analysis_input_id` 변경 | 미작성 |
| `reproduce`에 없는 환경변수 변경 | 결과 **불변**(원칙 검사) | 미작성 |
| `reproduce`만으로 id 재계산 | 인쇄된 값·해시만으로 `analysis_input_id`를 다시 만들어 대조(D111). 커밋 목록은 `commit_list_sha256` | 미작성 |
| 두 머신 바이트 동일 | 같은 입력 → 바이트 동일 산출물 | 미작성 |

## 주의

`repository_state_id`는 **추적/미추적 무관**하게 git blob 공식 `sha1("blob <size>\0" + bytes)`로 계산한다(§2.8) — 커밋되지 않은 파일도 트리 정체성에 들어간다. 케이스는 이 성질을 반드시 하나 덮어야 한다.
